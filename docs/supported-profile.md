# Supported profile

What rvt-rs can be trusted with today, in the terms a BIM user would check.
The evidence behind every line is in [`support-matrix.json`](support-matrix.json)
(`rvt-capabilities --matrix -f text` prints it) and in the measured tables of the
[evidence page](evidence.md#what-rvt-rs-reads-from-real-projects). This page
describes `main`; the latest release is v0.18.0, and what has landed since
is in the fragments under [`changelog.d/`](../changelog.d/README.md). Every number
below names the model it was measured on, and says "local only" or "not shared"
when nobody else can fetch that model, so nobody else can re-run it. The
[model index](reference-models.md#model-index) lists the models, and
[re-run the numbers](reference-models.md#re-run-the-numbers) is the command for
the numbers on the models anyone can fetch; nobody has yet re-run this page's
numbers from it and compared them. CI checks the rule on this page and the
README.

## Four levels of "it works"

A Revit file can succeed at one level and not the next, so rvt-rs keeps them
apart:

1. **Opened.** The OLE container, its streams, metadata, previews and schema
   read: every Revit release from 2016 to 2027, across the family corpus.
   Revit 2015 files open too, on Autodesk's sample projects, where previews
   and PartAtom are not measured.
2. **Elements identified.** Each element is found with its Revit ElementId and
   category, and the set equals the one Revit's own IFC export holds. Revit
   2024 and 2025 project files, and Revit 2023 ones with their bounding boxes
   only (RE-81). Experimentally, Revit 2026 ones, measured so on one project,
   flowbim's `AA-SingleDwellingHouse` (local only, RE-124), and Revit 2015 to
   2022 and 2027 ones, which have no measured Revit export of their own release
   (except two projects, BIMcollab's 2015 structural example, RE-198, and
   Vitoria's 2018 `ALD26 Before`, RE-315) and are measured against the same
   sample projects saved by Revit 2019 (for 2015 to 2018), 2023 (for 2019 to
   2022) and 2026 (for 2027) instead: a 2027 project's ElementIds and classes are its 2026 copy's, and
   on 2015 to 2022 every ElementId shared with the copy keeps its class, with
   the copy's building elements class for class where Autodesk did not edit
   the model between releases (the table below).
3. **Geometry.** An element's body. Exact where the element's data is decoded
   (the table below), otherwise its bounding box, and the export diagnostics
   say which.
4. **Properties.** Names, types, storey, materials, layers and GlobalIds are
   read; most other parameters are not (#35, #155).

A file that is corrupt, encrypted, a zero-byte Git LFS placeholder, or not an
OLE/CFB Revit container is refused with an error. A stream larger than
rvt-rs's resource limits (by default 2 GiB for the file, 256 MiB for one
stream and for one inflated member, and per partition 16 times its stored size
inflated, at least 1 GiB and at most 4 GiB, 1 GiB in a 32-bit build and in the
browser<!-- w10: the defaults of the limits in src/reader.rs, not a measurement -->) is not
read, so the elements it holds are not exported. `rvt-ifc` and `rvt-gltf` then
name each such stream, write no model and exit with status 3<!-- w10: the exit status the CLIs return, not a measurement --> unless
`--allow-partial`, and the diagnostics list them; `--large-model` raises the
per-stream cap to the file's own 2 GiB and, on a 64-bit machine, the inflate cap to 8 GiB<!-- w10: the presets of src/cli.rs, not measurements -->
(#1075). The readers of native records (types, materials, stairs, phases, saved
parameters and others) follow the same limits and skip only the stream they could
not read. The browser viewer opens a file at the default limits and, when a
stream is not read, reports "Part of the file not read" and offers "Retry
with large-model limits" (streams up to 2 GiB<!-- w10: the limit the viewer's retry sets, not a measurement -->); it stays under wasm32's 4 GiB<!-- w10: wasm32's address space, not a measurement -->
memory ceiling, so a very large model can still fail to open there. This is
measured by lowering the limits below the reference files' streams (Core
Interior's 17 MB partition against an 8 MiB limit). On the field report behind
#1075, the 438 MB client model (not shared, reported 2026-11-02 on 0.12.0),
whose largest partition is 403 MiB stored, exits with status 3 at the
defaults and reads with `--large-model` as 9,958 elements on 35 storeys at a
10.3 GB peak; the 1.13 GB client model, with a 1,057 MiB partition, was stopped
at its machine's 16 GB memory limit, so a model that size is not yet read.

A project saved by Revit 2024 to 2027 can keep the schema of the release it
passed through, and with it that release's element-record layout. Such a
file is read as the release its schema belongs to, and the diagnostics say
so ("Saved by Revit X but keeps Revit Y's schema"). A schema that matches no
measured release still reads no element records. The field report behind
#421 found this on 25 of 49 client models (not shared) saved by Revit 2024 to
2027, which 0.10.0 read as empty. None of the reference or sample files keeps an
older schema, so it is measured only on the reporter's files (not shared,
counts reported in #421 on 2026-11-02 and 2026-11-03 on 0.12.0):

- 17 of the client models (not shared) keep a 2024 or 2025 schema: the warning
  names the right releases on all 17. Against the reporter's own patched
  reader, element counts are equal on 6 client models and within 0.8% on 10,
  and storeys equal on 16; one client model has 10 storeys where theirs had 4,
  which they think is right. One client model exports 897 elements where
  theirs gives 1,075: 63 of the difference are elements outside the export
  phase, which rvt-rs leaves out as Revit's export does (RE-184), and their
  reader keeps earlier phases. No Revit export of these files has been
  compared.
- 8 of the client models (not shared) keep a 2022 or 2023 schema: their
  `Global/ElemTable` was read as 12-byte records because the layout check
  tested the record's second id, which on these files holds an older number.
  With the check on the ElementId (#421), the "fits neither" warning is gone on
  all 8 client models; two client models then export 10 and 1 elements, two
  keep their 1 and 4, and four still export none. Whether their ElementIds are
  Revit's was checked on one of the 8 client models, against the 13,279 element
  ids (598 of them types) that Revit 2024 listed for it (#421, 2026-11-04). Of
  the 5,555 records of that client model's table whose first two ids differ,
  3,734 hold a Revit id in the first only and 42 in the second only, so the
  first is Revit's ElementId there, though Revit upgraded the file in memory to
  open it, which may account for part of the 1,613 records that hold none. The
  other 7 client models are not checked.

## What approximations look like in the output

- A body that is the element's bounding box is a correctly placed, correctly
  sized box. It is never a guess at a shape.
- A file of a release read experimentally (Revit 2015 to 2022, 2026 and
  2027) says so: the export diagnostics' `input.release_support`, a warning,
  `rvt-inspect`'s `experimental_release` and the viewer's file status (#871).
- Where rvt-rs cannot tell something, it leaves it out rather than guess: an
  element whose storey is unknown sits in the building, not on a storey; a
  missing value is absent, not zero.
- `rvt-ifc --diagnostics out.json` and the viewer's diagnostics download list
  what was exported, approximated and skipped, and why, including every
  stream a resource limit kept from being read (`stream_not_read_resource_limit`). `--mode
  typed-no-geometry`, `geometry` and `strict` refuse a file that does not meet
  that bar instead of writing a thinner IFC.

## Not supported

- Converting an arbitrary Revit model to IFC with Revit-grade fidelity.
- Element records of releases other than 2008 to 2027. Of those, 2008 to 2022, 2026 and 2027 are experimental: 2008 to 2014, outside the 1.0 range, with 2008 to 2010 checked only for consistency within each local file (RE-260) and 2011 to 2014 measured on one local 2013 sample against its 2015 copy (RE-259); 2026 is measured on one project, flowbim's `AA-SingleDwellingHouse` (local only), against Revit's export (RE-124), and on two held-out projects, counts only, and since 0.6.0 2027 against the 2026 copies of Autodesk's sample projects (RE-179), 2019 to 2022 against their 2023 copies (RE-180), and 2015 to 2018 against their 2019 copies (RE-181), none with a Revit export of its own release except one 2015 project, BIMcollab's structural example (RE-198), and one 2018 project, Vitoria's `ALD26 Before` (RE-315), apart from the held-out projects of 2020, 2021, 2022 and 2027, counts only. On 2023 (since 0.4.0): geometry beyond each element's box, wall joins and beam cuts, layered or angled joins and IFC export overrides. On 2016 to 2023, elements in a non-primary design option (measured on Autodesk's `rst_basic` samples only, a `Mass` Revit does not export, with no Revit export of them) and outside the export phase (measured on the held-out Vitoria Project's counts only) are left out since RE-315.
- Semantic editing of a Revit file. `rvt-write` patches whole streams and
  preserves the rest byte for byte; it does not change model data.
- Door/Window typing from the opening-index rows (RE-19; the rows name
  system elements, not openings, RE-376) and Level ElementIds from the
  Formats schema (RE-20): both closed negative. Element records supply
  both instead.

Use `rvt-inspect <file> --json` or the viewer's diagnostics download when a
file falls outside this profile. Those reports can be attached to a GitHub
issue without sharing the model; [`CONTRIBUTING.md`](../CONTRIBUTING.md)
describes how to send a diagnostic instead of a building file.
