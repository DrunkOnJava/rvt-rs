# Develop in a Codespace

The repository's [dev container](../.devcontainer/devcontainer.json) provides
a Linux development machine for the Rust CLIs, Python bindings and browser
viewer. The same checkout works from a terminal, VS Code, Codex or Claude Code.
Each assistant has its own account sign-in, permissions and chat history.

## Create once

1. Check your personal [Codespaces usage](https://github.com/settings/billing)
   and [enforced budget](https://github.com/settings/billing/budgets).
   Included compute and storage are shared by **all** your Codespaces.
   GitHub Pro includes 180 core-hours (90 hours on a two-core machine) and
   20 GB-month of storage; Free includes 120 core-hours and 15 GB-month.
   Stopped machines still consume storage. Public repositories do not receive
   unlimited Codespaces compute. GitHub Actions billing is separate.
2. Open the repository's **Code → Codespaces → New with options**. Select
   the branch containing this configuration, the `rvt-rs` dev container,
   and **2 cores / 8 GB**. Do not create a replacement for a peer's machine.
3. Wait for the post-create command to finish. It installs the pinned CLI
   snapshots, the `viewer/package.json` pnpm version, stable Rust, Python
   3.12 from Ubuntu 24.04, and Chromium. It reuses `.cursor/install.sh` to
   build the native tools, Python binding and WASM viewer, then exercises
   a generated fixture through the CLI and browser.

The native build uses `profile.ci` (no release LTO); WASM uses `--dev`.
Cargo and Rayon default to two jobs in the container and SSH login shell.
Node's feature installs npm 12.2.0; pnpm comes only from the repository pin.
The wasm-pack 0.14.0 pin and Python hash-locked requirements remain shared
with Cursor setup. No corpus downloads, prebuild fleet or unit tests run.
The image digest and assistant CLI snapshots are deliberate reproducibility
pins; refresh them with remote invocation evidence when maintaining the image.
Features track their official major release; Rust tracks stable and Node 24
tracks its supported patch releases. Record the actual versions in evidence.

Post-create logs, CLI outputs and a browser screenshot are under
`/workspaces/.rvt-rs-evidence/rvt-rs/create-<timestamp>-<pid>/`.
Failures preserve their logs and fail setup. To inspect one, use `less` or
`sed -n '1,160p' <log>`. A resume only checks the environment and binding;
it does not reinstall, rebuild or start a server.
Bootstrap output is also recorded directly in the visible creation terminal,
with the command's exit status preserved.

## Terminal and SSH

On the computer running your desktop apps, authenticate GitHub CLI with
the `codespace` scope, then select the specific rvt-rs machine:

```bash
gh auth refresh -h github.com -s codespace
gh codespace list --repo DrunkOnJava/rvt-rs
gh codespace ssh -c YOUR_RVT_CODESPACE
```

Inside it, the checkout is `/workspaces/rvt-rs`. Use normal Git branches;
push source before stopping. To generate OpenSSH entries locally:

```bash
gh codespace ssh --config -c YOUR_RVT_CODESPACE > ~/.ssh/rvt-codespaces
```

Add `Include ~/.ssh/rvt-codespaces` to `~/.ssh/config` **before** general
`Host *` defaults, preserving existing entries. Use the concrete `Host`
alias generated by GitHub in `ssh ALIAS`; keep its `ProxyCommand` and key
settings intact. The container includes sshd and SFTP for desktop clients.
Do not expose sshd or an assistant app server as a public forwarded port.

## Desktop clients

| Client | Entry point | Authentication and verification |
| --- | --- | --- |
| Codex / ChatGPT desktop | Settings → Connections → SSH; enable the concrete OpenSSH alias, then add `/workspaces/rvt-rs` | Run `codex login` on the remote machine using the subscription sign-in flow. Verify `bash -lc 'command -v codex; codex login status'` over SSH before connecting. The app starts the remote Codex server through the login shell. |
| Claude desktop Code tab | Environment selector → SSH connection; use the same OpenSSH alias and checkout | macOS/Linux desktop versions with OpenSSH support honor `ProxyCommand`. SFTP and multiple SSH sessions are required. Desktop installs its own remote helper. Verify this route in the app; a working CLI alone does not prove it. |
| Claude Code terminal | `claude` in the remote checkout | Sign in to the intended subscription independently. Never set an API key as an automatic fallback. |
| VS Code desktop | Codespaces extension → Connect to Codespace; or `gh codespace code -c YOUR_RVT_CODESPACE` | GitHub sign-in is separate from either assistant. The Rust/Python/Claude extensions are recommended in the container. |
| Browser | Open the machine from GitHub Codespaces | Browser VS Code is also available; it does not transfer local Chrome sign-ins or native desktop apps. |

Codex's **Work in → Cloud** uses OpenAI's environment service. This Codespace
is an **SSH remote project**. Verify the remote host and checkout in a chat
before claiming desktop setup is complete. Starting another assistant session
or selecting a different provider/model needs its own authorization.

`AGENTS.md` is the shared public repository instruction source. Root
`CLAUDE.md` imports it. Keep personal hooks, credentials and Mac paths out of
the image and public repository. Do not copy `.ssh`, `.codex` or `.claude`
trees from a personal computer. Sign-ins in the container home generally
survive stop/start, but a rebuild can replace that home; sign in again if
needed. Do not persist credentials by writing them into `/workspaces` or
committing them. Use repository-scoped Codespaces secrets only when needed.

## Work and verify remotely

```bash
cd /workspaces/rvt-rs
cargo build --locked --profile ci
bash .devcontainer/resume.sh
bash .devcontainer/verify.sh /workspaces/.rvt-rs-evidence/manual-check
tools/ci/verify-real-files.sh --profile ci
cd viewer
CI=1 pnpm exec playwright test --config playwright.config.ts --workers=1
pnpm run dev --host 0.0.0.0
```

Port 5173 is forwarded **privately**. Confirm its visibility in the Ports
panel before opening it. Browser checks bind preview port 4173 to loopback.
Use `gh codespace ports forward 5173:5173 -c YOUR_RVT_CODESPACE` for local
access without making it public. Stop the foreground server with Ctrl-C.
The smoke script saves `viewer-smoke.png`, `browser.json`, the exact source
SHA, CLI output, IFC and diagnostics. Open the screenshot for visual review.
Synthetic fixtures prove parser/scaffold paths, not real Revit geometry.
External corpora are opt-in; follow [corpus intake](corpus-intake.md) and
[corpus sources](corpus-sources.md). Do not copy private oracle material.
Linux Codespaces cannot supply Revit-hosted Windows oracle execution.

For native release artifacts, explicitly use `cargo build --locked --release`.
For release WASM, run the usual wasm-pack command with `--release`. Do not
claim the development smoke as release, deployment or real-corpus proof.

## Resume, rebuild and retain

Use a 30-minute idle timeout and a 30-day retention period for the initial
machine. Closing a browser tab or desktop connection does not stop compute.
Stop your owned machine from the Codespaces list when idle; do not stop a
peer's machine. Reconnect the same machine to preserve `/workspaces`.
Review the machine's **auto-delete date** and update retention if needed.
Idle stop is best effort; terminal activity can keep a machine running.

`/workspaces` survives a container rebuild; container-home tooling and browser
caches may need reinstalling. Cargo output is in `target/`; the virtualenv,
`viewer/pkg`, `viewer/dist` and pnpm modules are regenerable, ignored outputs.
Never delete caches during an active build. A distinct worktree has its own
output directories; budget their storage. Do not bind all worktrees to one
shared Cargo target directory while different agents build concurrently.

Concurrent clients use separate branches/worktrees and one landing owner:

```bash
git worktree add /workspaces/rvt-codex -b codex/MY_TASK
git worktree add /workspaces/rvt-claude -b claude/MY_TASK
```

Run the shared bootstrap in a new worktree when its artifacts are needed.
Before deletion or expiry, push every owned branch and export unique evidence
to durable storage. `/workspaces` is persistent for that machine, **not a
backup after Codespace deletion**. No automatic cleanup of unpushed source,
credentials, peer work or unique evidence is configured.
