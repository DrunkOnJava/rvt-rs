## 1. The question

The BIM4LCA timber office at building permit holds walls with no `IfcWallType`, no layer set and so no `Width` or `Reference`: 8 of the type `VS-2.CLTpinta` (3408088) and 4 of `SPR-1` (2435488) before RE-444 (#1799), and 2 more of `VS-2.CLTpinta` after it, which retypes walls 1436343 and 2114950 from `VS-2` (1351396, 0.176 m) to a type whose width Revit's export gives them as 0.158 m. The type's name is read; its layers are not. Why?

## 2. What the bytes say

## 5. The change

`scan_type_layers` (`partition_compound_structure.rs`) took a type's layers from every partition's copy of its data and dropped a type whose copies gave different lists. A wall, floor, roof or ceiling type edited after an earlier save is rewritten into a newer partition and the older copy stays, so every type edited since had no layers and its walls no `IfcWallType`, `Width` or `Reference`. `choose_copy` now takes, where the copies disagree, the copies of the partition `native_document::current_partitions` names (the one the element index routes the type to, else the latest that holds a copy, RE-145 and RE-216; the transform reader's rule, `CopyRule::Current`), and takes none if no partition is named, none of the decoded copies is in it, or its copies disagree among themselves. The element's provenance names the copy: `wall_type_layers` and `roof_type_layers` have the rule `current` where the type's copies disagree (`docs/export-diagnostics.md`). **Only on Revit 2024 and later** (the layout with 64-bit ids, the criteria page's 1.0 scope): on Revit 2008 to 2023 a type whose copies disagree stays dropped, for the held-out file of row 3. Five failure-first tests of `choose_copy`, a pure function on layer lists (copies that agree take the first whatever the routing, copies that disagree with no routing take none, a routed partition is taken and not the highest-numbered, a routed partition without a decoded copy takes none, a routed partition whose copies disagree takes none).
