# RE-109 — Revit 2023 family instances' family and type names

**Date:** 2026-09-28
**Issues:** #421; follows RE-26, RE-38 and RE-81
**Artefacts (local only, no licence):** `255ribeiro/intro_ifc` `Exemplo_data.rvt` and `modelo_bim.rvt` (Revit 2023), each with Revit's own IFC4 export.
**Result:**
- **The name entry.** RE-38's name entry on 2024 and 2025 is `u64 id · u32 n · UTF-16 name · i64 category`. On Revit 2023 it is `01 00 00 00 · u32 id · u32 n · UTF-16 name`, with no category after the name. The same shape also frames a lone `U+FFFF`, which is not a name: only printable names are read. An id with two different names gets neither.
- **The type.** A 2023 element record names its type in its reference list, anywhere in it. It can come after the element's own id (a type made after the instance has the larger id), and another type can sit between them. So RE-26's rule (the last type slot before the own id) misses some. The type is the one id in the list that is a type record (placement kind `0xffff8000`) of the element's own category and has a name entry.
- **The family.** It is the one id the type's own record references that has a name entry and no element record.
- **Result.** Each family instance then carries `Family:Type`, and its IFC Name is `Family:Type:ElementId`, as Revit writes it.

## 1. Measured

- **The type join.** It is right, and unique, on every family instance of both exports: 27 of 27 and 31 of 31 element records whose Revit type has a type record. RE-26's rule left 7 of Exemplo_data's unnamed.
  - Door 337211's type 358762 comes after its own id.
  - Window 349606 lists 349494, its type, and then 349592 before its own id.
- **The family join.** Before U+FFFF was excluded, 8 of Exemplo_data's 11 types had 2 to 4 candidates, the others framing a lone U+FFFF. With it excluded, all 16 types of the two files have exactly one, and it is Revit's family name.

## 2. What is left

System-family types have no type record on 2023, and their name is not in this entry form: walls (`Parede básica:Genérico - 200 mm`), floors and roofs. On 2024 they are read from the schema's serialised data (#322). They keep their category's name: Exemplo_data's 17 walls and slab, and modelo_bim's 4 walls, slab and roof.

## 3. Other files

Every 2024 and 2025 file is byte-identical to main's apart from the timestamp. `Revit_IFC5_Einhoven.rvt` (2023, no local Revit export) names its family instances by the same rule.
